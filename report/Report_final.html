# 2. Define Network Parameters
Din = 3 * 32 * 32      # Input size (flattened CIFAR-10 image size)
K = 10                 # Output size (number of classes in CIFAR-10)
std = 1e-2             # Value was changed from 1e-5 (to better suit two layers)

# Define Middle Layer Parameters (Q1 (a))
H = 100                                  # number of nodes in the middle layer
torch.manual_seed(0)                     # added for reproducibility
w1 = torch.randn(Din, H) * std           # layer 1: input -> middle
b1 = torch.zeros(H)
w2 = torch.randn(H, K) * std             # layer 2: middle -> output
b2 = torch.zeros(K)

# Hyperparameters
iterations = 10     # 10 epochs
lr = 0.05         # Learning rate
lr_decay = 0.9      # Learning rate decay
reg = 0             # Regularization
loss_history = []

Q1(a): Network architecture¶

The single dense layer of Listing 1 was replaced by two layers:

$$z_1 = xW_1 + b_1,\quad h = \sigma(z_1),\quad \hat y = hW_2 + b_2$$

with $x\in\mathbb{R}^{3072}$, $h\in\mathbb{R}^{100}$ and $\hat y\in\mathbb{R}^{10}$, where $\sigma(z)=1/(1+e^{-z})$. This gives 3072·100 + 100 + 100·10 + 10 = 308,310 trainable parameters. Weights were initialised from a normal distribution with std 0.01 and biases to zero.

Random weights break the symmetry between hidden nodes, which would otherwise all receive identical gradients.

The sigmoid adds non-linearity. Without it, the two stacked linear layers would collapse into one linear map.

Hyperparameters. Batch size 50, 10 epochs, learning rate 0.05 decayed by 0.9 after each epoch, no regularization (reg = 0). The listing's values (std = 1e-5, lr = 2e-6) were designed for a single linear layer. With lr = 2e-6 the loss stayed at about 2.3036 for all 10 epochs (ln 10 ≈ 2.3026, the loss of a uniform guess), so the network did not learn (the 2e-6 run used std=0.01 as well). The updates were too small. lr = 0.05 was chosen because it trains smoothly; it was not tuned further.

# 3. Training Loop
for t in range(iterations):
    running_loss = 0.0
    for i, data in enumerate(trainloader, 0):
        # Get inputs and labels
        inputs, labels = data
        Ntr = inputs.shape[0]                                           # Batch size
        x_train = inputs.view(Ntr, -1)                                  # Flatten input to (Ntr, Din)
        y_train_onehot = nn.functional.one_hot(labels, K).float()       # Convert labels to one-hot

        # Forward Pass with 2 layers
        z1 = x_train.mm(w1) + b1                                        # middle layer pre-activation
        h = 1.0 / (1.0 + torch.exp(-z1))                                # sigmoid activation
        y_pred = h.mm(w2) + b2                                          # output layer scores (logits)

        # Calculating Cross-Entropy Loss
        z = y_pred - y_pred.max(dim=1, keepdim=True).values
        e = torch.exp(z)
        p = e / e.sum(dim=1, keepdim=True)                              # softmax probabilities
        loss = -torch.log(p[torch.arange(Ntr), labels]).mean() \
               + reg * (torch.sum(w1 ** 2) + torch.sum(w2 ** 2))        # cross-entropy + regularization

        loss_history.append(loss.item())
        running_loss += loss.item()

        # Backpropagation
        dy_pred = (p - y_train_onehot) / Ntr                            # softmax + cross-entropy gradient

        dw2 = h.t().mm(dy_pred) + reg * w2
        db2 = dy_pred.sum(dim=0)
        dh = dy_pred.mm(w2.t())                                         # push gradient back through w2
        dz1 = dh * h * (1 - h)                                          # sigmoid derivative
        dw1 = x_train.t().mm(dz1) + reg * w1
        db1 = dz1.sum(dim=0)

        # Parameter update
        w2 -= lr * dw2
        b2 -= lr * db2
        w1 -= lr * dw1
        b1 -= lr * db1

    # Print loss for every epoch
    if t % 1 == 0:
        print(f"Epoch {t + 1}/{iterations}, Loss: {running_loss / len(trainloader)}")

    # Learning rate decay
    lr *= lr_decay

print(f"Loss before any learning: {loss_history[0]}")

Q1(a): Backpropagation through the two layers¶

The gradient is propagated backwards with the chain rule:

$$dW_2 = h^\top d\hat y,\quad db_2=\sum d\hat y,\quad dh = d\hat y\,W_2^\top$$ $$dz_1 = dh\odot h\odot(1-h),\quad dW_1 = x^\top dz_1,\quad db_1=\sum dz_1$$

The factor $h(1-h)$ is the sigmoid derivative $\sigma'(z)=\sigma(z)(1-\sigma(z))$. Each backward line mirrors one forward line: a matrix product $aW$ gives $dW=a^\top dz$ and $da=dz\,W^\top$. Parameters are then updated by plain gradient descent, $W \leftarrow W - \eta\,dW$.

Q1(b): Cross-entropy loss¶

The scores are converted to probabilities with softmax,

$$p_k = \frac{e^{\hat y_k}}{\sum_j e^{\hat y_j}}$$

The largest score is subtracted first so that the exponentials don't overflow. This does not affect the result.

Cross-Entropy loss only looks at the probability given to the correct class and penalizes it for being small.

$$L = -\frac{1}{N}\sum_{n} \ln p_{n,\text{correct}}$$

(For example, if the correct class gets probability 0.9 the loss for that image is 0.11; if it gets 0.1, the loss would be 2.30. When training starts, all 10 classes start at about 10% probability. So, the loss would start at $\approx2.30$, as observed above.)

Combining softmax and cross-entropy gives a gradient of (predicted probabilities - one-hot labels). In code: 'dy_pred = (p - y_onehot) / N'. This replaces the MSE gradient of the listing, $(2/N)(\hat y - y)$.

# Q2(a) - LeNet-5
class LeNet5(nn.Module):
    def __init__(self):
        super().__init__()
        self.c1 = nn.Conv2d(1, 6, 5, padding=2)    # 28x28 -> 28x28 (padding=2 mimics LeNet's 32x32 input)
        self.c2 = nn.Conv2d(6, 16, 5)              # 14x14 -> 10x10
        self.f1 = nn.Linear(16 * 5 * 5, 120)
        self.f2 = nn.Linear(120, 84)
        self.f3 = nn.Linear(84, 10)
    def forward(self, x):
        x = F.avg_pool2d(torch.tanh(self.c1(x)), 2)    # -> 6 x 14 x 14
        x = F.avg_pool2d(torch.tanh(self.c2(x)), 2)    # -> 16 x 5 x 5
        x = x.flatten(1)
        x = torch.tanh(self.f1(x))
        x = torch.tanh(self.f2(x))
        return self.f3(x)                              # 10 raw scores

# Q2(b) - Modern small CNN: 3 conv layers + batch norm + dropout
class SmallCNN(nn.Module):
    def __init__(self):
        super().__init__()
        def block(i, o):                               # conv -> batch norm -> ReLU -> downsample
            return nn.Sequential(nn.Conv2d(i, o, 3, padding=1), nn.BatchNorm2d(o),
                                 nn.ReLU(), nn.MaxPool2d(2))
        self.features = nn.Sequential(block(1, 32), block(32, 64), block(64, 128))  # 28 -> 14 -> 7 -> 3
        self.drop = nn.Dropout(0.5)
        self.fc = nn.Linear(128 * 3 * 3, 10)
    def forward(self, x):
        return self.fc(self.drop(self.features(x).flatten(1)))

Q2(a) and (b): Models¶

LeNet-5 (61,706 parameters): two 5×5 convolution layers (6 then 16 filters), each followed by tanh and average pooling, then three fully connected layers (120, 84, 10). Tanh and average pooling was used as per the original paper. Padding of 2 in the first layer lets the 28×28 MNIST images behave like LeNet's original 32×32 input.

Small CNN (104,650 parameters): three 3×3 convolution blocks (32, 64, 128 filters), each with batch normalization, ReLU and 2×2 max pooling, then dropout (p = 0.5) and one fully connected layer. Batch normalization rescales each layer's outputs, which usually makes training faster and more stable. Dropout randomly switches off half of the features during training, which discourages the network from relying on any single one.

Training conditions (identical for both): MNIST, cross-entropy loss, Adam with learning rate 0.001, batch size 64, 10 epochs, same random seed. Train and test metrics were computed after every epoch with dropout off.

def evaluate(model, loader):
    model.eval()                                       # switches off dropout, batch norm uses stored statistics
    loss_sum, correct, total, preds, truth = 0.0, 0, 0, [], []
    with torch.no_grad():
        for x, y in loader:
            x, y = x.to(device), y.to(device)
            out = model(x)
            loss_sum += F.cross_entropy(out, y, reduction='sum').item()
            pred = out.argmax(1)
            correct += (pred == y).sum().item(); total += y.size(0)
            preds.append(pred.cpu()); truth.append(y.cpu())
    return loss_sum / total, 100 * correct / total, torch.cat(preds).numpy(), torch.cat(truth).numpy()

def train_model(model, epochs=10, lr=1e-3):
    model.to(device)
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    hist = dict(train_loss=[], train_acc=[], test_loss=[], test_acc=[])
    for ep in range(epochs):
        t0 = time.time()
        model.train()                                  # dropout on, batch norm uses batch statistics
        for x, y in mnist_trainloader:
            x, y = x.to(device), y.to(device)
            opt.zero_grad()
            F.cross_entropy(model(x), y).backward()
            opt.step()
        # Q2(c) - log loss and accuracy on both sets after every epoch (both in eval mode)
        trl, tra, _, _ = evaluate(model, mnist_trainloader)
        tel, tea, _, _ = evaluate(model, mnist_testloader)
        for key, val in zip(hist, (trl, tra, tel, tea)):
            hist[key].append(val)
        print(f"Epoch {ep+1:2d}/{epochs}  train loss {trl:.4f} acc {tra:.2f}%  |  "
              f"test loss {tel:.4f} acc {tea:.2f}%  ({time.time()-t0:.0f}s)")
    return hist

Q2(c): Training curves¶

Both models improve quickly in the first epochs. The small CNN is already at 98.33% test accuracy after one epoch, while LeNet-5 needs several epochs to pass 98.5%, which fits the faster training that batch normalization usually gives. The small CNN's test accuracy stays above LeNet-5's at every epoch.

LeNet-5's training loss keeps falling, but its test loss stops improving after about epoch 6 (0.039) and then rises slightly, so it starts to overfit mildly. The small CNN's test loss stays roughly flat at about 0.022, and its train/test accuracy gap is smaller (0.55 vs 0.85 points), consistent with dropout limiting overfitting. The test curves are noisy from epoch to epoch, so small differences between neighbouring epochs shouldn't be over-interpreted.

Q2(c): Confusion matrices¶

Both matrices are strongly diagonal. The most common mistake for both models is a true 9 predicted as 4 (10 times for LeNet-5, 14 for the small CNN). The reverse (4 predicted as 9) is rare, so the confusion is one-directional. A likely reason for this is that handwritten 9s with a small or open loop look like a 4. LeNet-5 also confuses [3→5] (10) and [7→1] (7) noticeably, and the small CNN almost removes these (3 and 1). The pair 9→4 got slightly worse for the small CNN even though its total errors fell from 128 to 74, so the improvement is not uniform. The 2→7 confusion is essentially unchanged (6 and 7), which suggests those test digits are genuinely ambiguous.

Q2: Summary¶

The small CNN gives higher test accuracy (99.26% vs 98.72%), converges faster and overfits less, at the cost of more parameters. The two experiments (Q1 and Q2) use different datasets (CIFAR-10 and MNIST), so their accuracies cannot be directly compared. What the two experiments do show is that convolutional layers, which look at local patterns and share weights across positions, suit images better than a network that flattens the image into an unrelated vector.

Q3: Data and approach¶

The hymenoptera dataset has 244 training and 153 validation images of ants and bees (2 classes). Images were resized to 224×224 and normalised with the ImageNet mean and std, since ResNet18 was pretrained on ImageNet-1K. Training images also get random crops and horizontal flips (augmentation), which helps because the dataset is so small.

Both experiments start from the same pretrained ResNet18 with its 1000-class output layer replaced by a 2-class layer. They use identical training settings: SGD with momentum 0.9, learning rate 0.001 reduced by a factor of 10 every 7 epochs, batch size 4, 25 epochs. The only difference is which weights are allowed to change.

# One training function for both (a) and (b), so conditions are identical
def train_hym(model, optimizer, scheduler, epochs=25):
    best_w, best_acc = copy.deepcopy(model.state_dict()), 0.0
    hist = {'train_acc': [], 'val_acc': [], 'train_loss': [], 'val_loss': [], 'time': []}
    for ep in range(epochs):
        t0 = time.time()
        for phase in ['train', 'val']:
            model.train(phase == 'train')              # train mode: batch norm uses batch statistics
            loss_sum, correct = 0.0, 0
            for x, y in hym_dl[phase]:
                x, y = x.to(device), y.to(device)
                optimizer.zero_grad()
                with torch.set_grad_enabled(phase == 'train'):   # no gradients needed for validation
                    out = model(x)
                    loss = F.cross_entropy(out, y)
                    if phase == 'train':
                        loss.backward(); optimizer.step()
                loss_sum += loss.item() * x.size(0)
                correct += (out.argmax(1) == y).sum().item()
            if phase == 'train':
                scheduler.step()                       # lower the learning rate on a schedule
            n = len(hym_ds[phase])
            hist[phase + '_acc'].append(correct / n)
            hist[phase + '_loss'].append(loss_sum / n)
        hist['time'].append(time.time() - t0)
        if hist['val_acc'][-1] > best_acc:             # remember the best epoch (by validation accuracy)
            best_acc, best_w = hist['val_acc'][-1], copy.deepcopy(model.state_dict())
        print(f"Epoch {ep+1:2d}/{epochs}  train acc {hist['train_acc'][-1]:.3f}  "
              f"val acc {hist['val_acc'][-1]:.3f}  ({hist['time'][-1]:.0f}s)")
    model.load_state_dict(best_w)                      # go back to the best epoch's weights
    return model, hist, best_acc

Q3: Comparison and discussion¶

Best val acc Last-epoch val acc Trainable parameters Time per epoch
(a) Fine-tuning 93.46% 90.85% 11,177,538 18.1s
(b) Feature extractor 95.42% 94.77% 1,026 15.9s

The feature extractor did at least as well as fine-tuning here. Its best validation accuracy was 95.42% (146 of 153 images) against 93.46% (143 of 153), a gap of 3 images. On the last epoch the gap is larger: 94.77% against 90.85%, or 6 images. Each image is worth 0.65 points and this is a single run, so the feature extractor is competitive and probably slightly better, but not clearly better. A likely reason is the very small dataset: updating 11 million weights from 244 images can disturb good pretrained features, whereas training only the last layer cannot. Features learned on ImageNet (edges, textures, shapes, animal parts) already separate ants from bees well.

The feature extractor trains far fewer parameters (1,026 vs 11.2 million) and does no backward pass through the backbone, but its time per epoch was only about 12% lower (15.9 s vs 18.1 s). With a small dataset and batch size 4, much of the time is probably spent on loading and augmenting images and on the forward pass, which both approaches share. Epoch times also varied between about 13 and 20 seconds, so this difference should not be over-interpreted. With a larger dataset, or one very different from ImageNet, fine-tuning would be expected to gain more.

For the feature extractor, training accuracy stays below validation accuracy at every epoch (about 90% vs 95% at the end). For fine-tuning the two are about equal in later epochs. This is because training images are randomly cropped and flipped, which makes them harder than the fixed center-cropped validation images. Also, the best epoch is chosen using the same validation images that the accuracy is reported on, so "best val acc" is slightly optimistic. The last-epoch value is a fairer estimate.
